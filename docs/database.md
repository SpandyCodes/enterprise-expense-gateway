# Database

PostgreSQL, accessed via SQLAlchemy 2.x async ORM, versioned with
Alembic. See `app/models/` for entity definitions and
`docs/reporting_views.sql` for the reporting views layer.

## ER diagram (textual)

```
users ---------------------------< expense_reports >--------------- approvals
  |  (manager_id self-FK)              |                                |
  |                                    v                                |
  |                              expense_items >-------- expense_types  |
  |                                    |                                |
  |                                    v                                |
  |                              audit_results < ----------- audit_rules|
  |
  +-- (INTEGRATION_SERVICE role users are also `users` rows)

integration_logs      (independent — correlation_id links to a batch of
                        related log rows across retries)
idempotency_records    (independent — keyed by Idempotency-Key)
```

Key relationships:
- `expense_reports.user_id -> users.id`
- `expense_items.report_id -> expense_reports.id`
- `expense_items.expense_type_id -> expense_types.id`
- `approvals.report_id -> expense_reports.id`, `approvals.approver_id -> users.id`
- `audit_results.report_id -> expense_reports.id`, `.rule_id -> audit_rules.id`, `.expense_item_id -> expense_items.id` (nullable)
- `users.manager_id -> users.id` (self-referential)

## Indexes

Per the spec, indexes exist on: `users.employee_id`,
`expense_reports.report_number`, `expense_items.transaction_date`,
`expense_reports.status`, `integration_logs.correlation_id`,
`integration_logs.created_at`, `idempotency_records.idempotency_key`.

## Migrations

```bash
alembic revision --autogenerate -m "initial schema"
alembic upgrade head
alembic downgrade -1
```

See `alembic/versions/README.md` for the exact first-run sequence,
including the separate migration for reporting views (raw SQL, not
autogenerated).
